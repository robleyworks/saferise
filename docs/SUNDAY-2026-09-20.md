## Track 1 — code. No artwork needed. ~9.95 MB recovered.

Run `pass/PASS-C-IMAGE-MARKUP.md` in Claude Code. In this order, because the
value is front-loaded:

- [ ] **1.1 — Use the WebP siblings that already exist.** 34 files. **6.45 MB.**
      Zero new assets: the `.webp` is already next to the `.jpg` and the markup
      loads the wrong one. `<picture>` wrapper. List: `docs/webp-worklist.json`
      → `have_webp`. *This is the single largest win available anywhere in the
      image work, and it is markup only.*
- [ ] **1.2 — Generate the 35 missing WebP.** **3.50 MB.** One batch.
      **25 opaque** → `cwebp -q 78 -m 5`.
      **10 with transparency** → `cwebp -q 80 -m 5 -alpha_q 100`.
      The ten are the galaxy subject cutouts. Encoding them as RGB destroys the
      alpha and the cutout with it. Verify the alpha channel survived on all ten
      before committing.
- [ ] **1.3 — `width` and `height` on all 188 `<img>`.** Every single tag lacks
      them today; that is the page-jump on load. Values are already measured in
      `docs/image-intrinsic-dims.json` — look up, don't measure. Add
      `decoding="async"` throughout and `loading="lazy"` below the fold only.
- [ ] **1.4 — Alt-text audit.** Three buckets: decorative gets `alt=""`,
      meaningful gets a real description, missing gets eliminated. Claude Code
      should hand back a list of photographs it can't describe rather than
      inventing descriptions.
- [ ] **1.5 — srcset, only where it pays.** Four slots: `t1/hero.webp`,
      `coming/coming-hero.webp`, `home/door-t3.webp`, `coming/band-04.webp`.
      Not everywhere — covers render at a fixed 131px and gain nothing.
- [ ] **1.6 — Replace the JS variant selection** in `dashboard.html`
      (`+ '-640'` at :1056, `+ '-320'` at :1213) with real markup.
- [ ] **1.7 — The four-step separator.** One line: `content/tracks.js:7` uses
      slashes where every other label uses arrows. Plus the `&#8594;` entity in
      `live-sessions.html`, which is invisible but untidy.

**Verify:** `python3 audit/sr-imageweight.py`. Target: mobile total under
**2.6 MB** across the ten measured pages, from **6.27 MB** today.
