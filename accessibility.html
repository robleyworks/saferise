Accessibility

SafeRise Protocol is a product about nervous system regulation. Somebody arriving here may be tired, in pain, or unable to concentrate. Accessibility is not a compliance exercise for us — it is the same problem the product is about.

Where we stand

We are working toward WCAG 2.2 Level AA. We have not yet completed a full independent audit, so we are not claiming conformance. This page will change when that changes, and it will say so plainly.

What is in place

  • A skip-to-content link on every page
  • Semantic headings and landmark regions
  • Text alternatives on meaningful images; decorative images marked as such
  • A light and a dark theme, both selectable
  • Motion respects prefers-reduced-motion — animation does not start for anyone who has asked their system to reduce it
  • No time limits, no countdowns, no session expiry inside a protocol
  • No content that flashes
  • Written scripts for every guided audio session, so the audio is never the only route to the content

What we know is not finished

  • Colour contrast has not been verified across every component
  • Keyboard traversal of the protocol router and the audio player has not been fully tested
  • Screen reader testing has not been carried out on the member dashboard
  • Captions are not yet available on video

We would rather list these than leave them unsaid.

Tell us about a barrier

If something here is difficult or impossible to use, please write to contact@thesaferiseprotocol.com. Tell us the page and what happened. We aim to reply within five working days.

If you need something on this site in a different format, ask. We will send it.

If you are in crisis

SafeRise is not crisis support. If you are in immediate danger, contact your local emergency number. findahelpline.com lists free, confidential helplines by country.
